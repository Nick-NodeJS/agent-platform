# Modules and change map

Every workspace package and app, what it owns, and where to change things. Symbols are named, not copied, so this page does
not drift with signatures; read the linked file for the exact shape. Dependency direction: `contracts` ← everything;
`apps/*` depend on all packages; packages never depend on apps.

## What is real, mock, or unused today

| Item                                                                                    | State                                                                                                                                                         |
| --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `MockAgentExecutor`                                                                     | **Implemented mock.** Deterministic, offline, cost 0, outputs marked fictional                                                                                |
| `OpenHandsAgentExecutor`, `EXECUTION_MODE=openhands`                                    | **Stub.** Always throws `RealExecutionNotImplementedError` (a "not started" error); config requires `OPENHANDS_*` variables that nothing reads                |
| `ROLE_DEFINITIONS`, `assertProfileConfigured`, `ModelProfile` (provider, model, budget) | **Unused extension point.** Placeholder profiles; the CLI and worker declare the package but do not import it. The mock ignores instructions and budgets      |
| `loadPolicyContext`                                                                     | **Implemented, not wired.** Tested; no executor calls it yet because no coding/review agent exists                                                            |
| Roles `product-manager`, `architect`, `developer`, `qa`, `devops`                       | Names exist in `agentRoleSchema`; no stage, input/output types or executor support. Only `researcher` and `business-owner` are executable (`AgentRoleIO`)     |
| `cost_entries`, `execution_events` tables                                               | Written (cost always 0 for the mock). `status` and `executions` print cost totals; `execution_events` is write-only in practice. Budgets are **not** enforced |
| Review gate revision                                                                    | Always revision 1 (`gateIdFor`); there is no revise-and-resubmit flow                                                                                         |
| `TaskStore` adapters                                                                    | Only `LocalTaskStore`. Jira is a documented future adapter, not stubbed                                                                                       |
| Approvals with `source: 'agent'`                                                        | The schema allows an agent-sourced approval record; nothing creates one and the workflow never accepts it                                                     |

## Change map

Start from the entry point, then update the tests and the named docs.

| I want to change...                             | Edit                                                                                                                                                                                                        | Also update / check                                                                                                                                                |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Role instructions or model configuration        | `ROLE_DEFINITIONS` and `modelProfileSchema` (`packages/agents`, `contracts/agent.ts`); wire them into the executor you are adding (they are unused today)                                                   | [security](security.md) (credentials are env var **names** only); ADR 5                                                                                            |
| Workflow stages or approval policy              | [`workflows/index.ts`](../../apps/worker/src/workflows/index.ts) (order, timeouts), Activities in `activities.ts`, `STATUSES`/`WorkflowStatus` in contracts, pure gate rules in `approval.ts`               | **Replay compatibility** ([workflows](workflows.md)); status order in `RunRepository.updateStatus` and `LocalTaskStore`; [workflows](workflows.md) diagrams; ADR 3 |
| Executor or provider implementation             | Implement `AgentExecutor` (typed by `AgentRoleIO`) in `packages/integrations`; select it in `createExecutor`; honor `ExecutorNotStartedError` semantics                                                     | Output validation in `activities.ts` (`validateOutput`), timeouts vs the 1-minute Activity limit, [security](security.md), ADR 5                                   |
| Add a task-store adapter (for example Jira)     | Implement `TaskStore` in `packages/integrations`; pick it in `apps/worker/src/main.ts` and the CLI `status` command (which constructs `LocalTaskStore` directly)                                            | Idempotency and forward-only status rules; `locate()`; [overview](overview.md) data-authority table; ADR 2                                                         |
| Persistence schema or migrations                | New numbered file in [`migrations/`](../../packages/persistence/migrations/) (forward-only, never edit applied files); then `RunRepository` and its row schemas                                             | `pnpm db:migrate` on dev databases; integration tests; [overview](overview.md)                                                                                     |
| File locking or task projection                 | [`file-lock.ts`](../../packages/integrations/src/file-lock.ts), [`local-task-store.ts`](../../packages/integrations/src/local-task-store.ts)                                                                | Cross-process tests and the fixture `fixtures/store-child.ts`; [security](security.md) limits; ADR 4                                                               |
| CLI commands or progress output                 | A module in [`apps/cli/src/commands/`](../../apps/cli/src/commands/) plus the `switch` and `USAGE` in `cli.ts`                                                                                              | [`cli.integration.test.ts`](../../tests/integration/cli.integration.test.ts); examples in [workflows](workflows.md) and the README                                 |
| Quality policy, its loading, or CI verification | [`docs/code-quality.md`](../code-quality.md), `eslint.config.js`, `vitest.coverage.config.ts`, [`ci.yml`](../../.github/workflows/ci.yml), `pnpm verify` in `package.json`, `packages/agents/src/policy.ts` | Keep one verification order; coverage floor stays 80/80; [validation report](../validation-report.md)                                                              |
| Environment variables                           | Schemas in [`config.ts`](../../packages/contracts/src/config.ts), then [`.env.example`](../../.env.example) (names and dummy values only)                                                                   | [local development](../local-development.md)                                                                                                                       |

Rule of thumb: contracts change first, then adapters, then wiring (`main.ts`), then tests and documents. An executable change
that alters behavior, contracts, persistence, permissions or deployment must update the matching page here or an
[ADR](../decisions/README.md).
